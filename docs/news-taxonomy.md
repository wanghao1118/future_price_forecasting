# 新闻分类与归档规范

本规范用于原油期货相关新闻的公开采集、agent 审核与人工整理。分类描述新闻涉及的事情；影响方向需要结合品种、合约期限和市场预期单独判断。

## 10 个主分类

每条新闻选择一个最能概括其核心内容的主分类 `category`，并用 `categories` 保存所有具有正文依据的研究分类。同一条新闻可在多个类别下展示，数据库只保存一条记录；每个分类都有独立的 agent 判定依据。影响渠道标签另外描述作用途径。同一事件的后续报道可通过 `event_id` 关联；不能确定关联时留空。

| 编号 | 分类 ID | 主分类 | 收集范围 |
| --- | --- | --- | --- |
| 01 | `supply` | 原油生产与供应 | OPEC+ 产量决策及执行、产量与出口、油田投产停产、罢工、钻井和生产商资本开支 |
| 02 | `demand` | 消费需求与经济活动 | 主要消费国经济活动、交通航空、工业、消费、进口与需求预测修订 |
| 03 | `inventory` | 库存与战略储备 | 商业原油、库欣和成品油库存、海上浮仓、战略储备释放或回补 |
| 04 | `refining` | 炼厂与成品油 | 炼厂检修事故、开工率与加工量、炼油利润、汽柴油和航煤供需 |
| 05 | `geopolitics` | 地缘政治与国际制裁 | 战争袭击、停火谈判、产油国政局、制裁及豁免、制裁执行 |
| 06 | `logistics` | 运输、贸易与交付 | 海峡港口管道、油轮运费、战争险、改道、交付延迟和现货升贴水 |
| 07 | `macro` | 宏观金融与流动性 | 央行决策、通胀、美元与利率、信用风险、金融市场流动性 |
| 08 | `policy` | 能源政策与替代能源 | 进出口限制和配额、税收补贴、环保要求、替代燃料和能源转型政策 |
| 09 | `positioning` | 期货资金与交易制度 | 基金与套保持仓、保证金限仓、交割规则、指数调仓、合约到期 |
| 10 | `weather` | 天气与自然灾害 | 飓风严寒、洪水干旱、高温地震，以及受影响的设施与恢复进度 |

需要保留的分类边界：

- 以天气为核心的新事件归入天气；正文明确记录它影响的是油田、炼厂、港口还是消费。
- 以制裁或战争为核心的报道归入地缘；运费和交付后果增加运输渠道标签。
- OPEC+ 生产决策归入供应；涉及储备释放或回补的报道归入库存。
- 机构报告按本条新闻关注的核心指标归类，另外将来源性质标记为“机构预测”。报告中出现多项独立变化时，可以拆成多条记录并保持来源关联。

## 影响渠道

一条新闻可选择多个渠道：供应数量、消费需求、库存、炼厂加工、运输交付、风险溢价、汇率利率、资金交易。

例如，飓风导致炼厂关闭时，主分类为天气与自然灾害，渠道同时涉及炼厂加工和消费需求。炼厂停工可能减少当地原油采购，又减少成品油供应，对原油和汽油的方向可能不同。不要只用“能源利多”概括。

## 保存的 8 组属性

| 属性组 | 字段 | 记录要求 |
| --- | --- | --- |
| 时间 | `occurred_at`、`published_at`、`collected_at`、`effective_at` | 分别记录发生、首次发布、系统采集和生效时间；保留时区，不清楚时留空 |
| 来源与性质 | `source_name`、`source_url`、`source_type` | 保存原始来源和链接；区分事实公告、数据发布、机构预测、评论复盘、未经确认消息 |
| 对象 | `region`、`entities`、`assets`、`contract` | 保存国家地区、公司设施、相关品种 WTI/Brent/SC 和合约月份 |
| 事件阶段 | `stage` | 区分传闻、提议、宣布、实施、扩大、恢复、取消 |
| 数量与预期 | `actual_value`、`expected_value`、`previous_value`、`unit` | 实际值与发布前预期使用相同口径和单位；未知预期不要事后补造 |
| 规模与期限 | `scale`、`duration`、`horizon` | 记录受影响规模、预计持续时间，以及盘中、1–5 个交易日、数周或数月及以上的研究期限 |
| 方向与证据 | `direction`、`rationale`、`verification`、`confidence` | 方向为偏多、偏空、混合或不确定；说明依据，并区分待核验、已确认、存在争议；确信度为低、中、高 |
| 事件关联 | `event_id`、`update_note`、`is_demo` | 同一事件使用同一关联编号，说明本次新增信息；演示记录必须显式标记 |

此外，每条记录包含 `title`、`summary`、`body`、`category`、`categories` 和 `channels`。系统通过 `id` 标识单条新闻，并维护 `created_at`、`updated_at`。`id` 识别新闻记录，`event_id` 用来关联多条报道，不应混用。

真实采集记录另外保存 `ingestion`（来源 ID、站内 ID、规范原文 URL、原始响应路径、内容哈希、运行 ID）和 `agent_review`（审核者、审核时间、原油相关性及理由、各分类依据、原文证据、分类确信度）。Agent 判定相关不等于事实核验通过，初始 `verification` 为“待核验”。

## 归档与研究规则

### 实际值与预期差

库存下降不自动等于利多。假设市场预期去库 500 万桶，实际只去库 200 万桶，应同时保存这两个数值，注明去库弱于预期。OPEC+ 减产也需要区分公告规模、市场预期和实际执行。

### 品种与预测期限

方向标签针对指定品种及期限，不能根据事后涨跌倒填。WTI 需要关注美国、库欣和管道信息；Brent 需要关注国际供应与海运；SC 还需要关注中国进口、炼厂、人民币和交割条件。近月与远月可能反应不同，尽可能记录合约月份。

### 多时间与历史可用信息

建模时只能使用预测时点前已经公开且系统能够获得的信息。事件发生时间不能替代首次发布时间，数据所属周期也不能替代发布时间。保存当时可见的预期、初始发布值和后续修订信息，避免用修订后的历史数据回填旧记录。

### 去重与事件演进

转载同一消息时优先保留原始来源。宣布减产、实际开始减产和后续出口下降可能是同一事件的不同阶段，需要通过 `event_id` 关联，并在 `update_note` 中记录新增信息。保持阶段差异，避免将同一条旧消息重复计为独立冲击。

### 评论与行情复盘

“油价上涨，因为……”这类文章标记为评论复盘。它可能包含已经发生的价格变化，研究时需要与独立事件公告、数据发布分开处理，避免把行情之后的解释用于预测之前的行情。

纯报价、涨跌幅、技术点位或没有供需等因子依据的目标油价预测，不进入十类因子新闻。期货资金与交易制度必须有基金持仓、套保、资金流、移仓、保证金、限仓、交割或持仓披露制度的依据，不能把“期货涨跌”本身归入资金类。运输类别要求涉及原油、成品油或其供应链，普通商品和武器运输不据此归入原油运输。

## 实际采集与演示数据

初始数据用于展示分类、字段和页面交互，均为虚构示例，不能当作真实事件或训练样本。原有演示数据保留，网页默认只显示正式新闻。

采集流程先抓取公开候选和原始响应，再用 agent 逐条决定是否与原油相关、属于哪些类别，校验证据后写入对应类别。非相关候选和排除理由保留在审核记录中。网页不以关键词命中直接归档，也不把附件中的旧摘要当作新采集新闻。

没有相关新闻的类别保持为空。真实来源暂不可访问时记录失败，不编造新闻补齐分类。全部来源及接入状态见 `source-registry.md`。
