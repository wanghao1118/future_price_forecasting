# env01 v5：UTC 时分检索与预测前 30 分钟截止

新评估协议为 `env01-agent-search-close-direction-return-range-v5-utc-30m`，
检索策略为 `forecast-start-minus-30m-utc-v1`。新闻和技术指标共用以下截止：

```text
cutoff_utc = time_windows.forecast.start_utc - 30 分钟
```

例如预测交易区间从 `2026-09-26T08:00:00Z` 开始，截止为
`2026-09-26T07:30:00Z`。`Z` 和 `+00:00` 都表示 UTC+0。
开始时间使用冻结的完整交易区间起点，包括 SC 夜盘与跨日时段，不能把交易日标签当作午夜。
恰好等于截止的记录可以返回；晚于截止一分钟或不足一秒也不能返回。

## 调用顺序

1. 模型选择新闻关键词，或技术指标及查询时间段。
2. time gate agent 验证冻结交易区间，计算截止并注入宿主检索请求。
3. 接口结合检索条件和精确时间预筛选本地冻结快照。
4. time gate agent 独立复核召回记录的发布时间、可用时间及来源修订时间。
5. 仅将合格内容和精确 UTC 截止返回模型。

截止由宿主提供，模型不能通过参数更改截止、题目或快照。缺少已核实交易区间时拒绝启动新评估，
不退回按日期筛选。关键词、原始模型参数、宿主截止、预筛选和复核证据均保留。

## 新闻：search_news

模型参数：

```json
{"keywords":"原油 OPEC 库存","limit":5}
```

time gate 自动注入 `cutoff_utc`，不要求模型自行计算或传入。
接口先过滤 `published_at <= cutoff_utc`，再按关键词搜索；召回后复核首发时间、来源修订、
归档状态和品类。缺少时分、无时区、时间未核实或晚于截止的记录不释放。
返回的首发和修订时间统一为 UTC+0。

每题最多 8 次有效搜索，每次最多 8 篇；原文长度与响应字节预算沿用既有规则。
合法空结果为 `no_results`，可作为有效搜索保存。

## 技术指标：search_indicators

模型参数：

```json
{"indicator":"price","start_time":"2026-09-01T00:00:00Z","limit":366}
```

`start_time` 必须包含完整日期、时分和显式时区；可传 `end_time`，省略时默认使用宿主截止。
起点不得早于 `2026-01-01T00:00:00Z`。显式终点越过截止、起止颠倒、只有日期或没有时区，
整次返回 `rejected`、原因及 `allowed_start_time` / `allowed_end_time`，允许模型纠正重查。
无效查询不消耗 8 次有效查询额度，总尝试上限仍为 16 次。

接口按指标的精确 `available_at` 过滤，复核后每点返回 `available_at`、交易日标签、值与可用状态。
同时存在观测时间、可用时间和修订时间时，以最晚时刻为有效可用时间；修订也不得越过请求终点。
没有可核实时间的记录无法返回，不把日线交易日标签或图表的午夜排序锚点当成发布时间。
每次最多返回 366 点，截断时保留最新一段并明确标记。

技术快照优先保留来源自带的精确时间。只有交易日的已完成日线，用经核实的交易区间结束时间
作为完成时刻，并保存 `available_at_basis=verified_exchange_session_end` 和来源依据。
该依据表示交易区间参考，不代表供应商实际发布时刻已独立核实。无法核实时保持不可用。
派生指标的可用时间不得早于组成窗口内任一观测的可用时间。

## 审计和历史

两类响应与回执均绑定 `retrieval_time_policy`、`forecast_start_utc`、`cutoff_utc`。
保存的检索响应会通过原冻结快照重放验证，核对参数、内容、时间边界及哈希，不调用模型。
Codex CLI 与 AIHub 的两种调用通道使用相同参数校验与宿主检索实现。

旧 v2/v3/v4 的题目、回执和成绩保留原冻结协议；v4 的截止仍为开始前2小时，v5 的截止为开始前30分钟，新旧协议分别比较。
本次边界约束作用于两个检索接口，题干中已知行情仍遵循 Benchmark 输入规则；
部分市场的当前日线可能晚于检索截止，因此该日线不能再经指标接口返回。
本次变更不重跑历史模型，不自动重建题库。
